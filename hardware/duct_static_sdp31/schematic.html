SDP31 Duct Static Node

A Sensirion SDP31 differential-pressure sensor on an ESP32 over I²C, reporting duct static pressure to Home Assistant over Wi-Fi through ESPHome. It is a separate device from the Trane CAN recorder and never touches the CAN bus.

range ±500 Pa = ±2.0 inWC your peak ≈ 1.0 inWC (249 Pa) at 100 % blower I²C 0x21 VDD 2.7–5.5 V · run it at 3.3 V

About the part name

Sensirion doesn't make an "STB 31", so this drawing uses the SDP31 (±500 Pa). Don't substitute the SDP32: it tops out at ±125 Pa (0.5 inWC), about half the static your blower makes on fan-On. The SDP810-500Pa is a drop-in alternative with barbed tube ports. The wiring is identical; change address: 0x21 to 0x25.

  • Never tie ADDR to VDD. Tied to GND it gives address 0x21. 1.2 kΩ to GND gives 0x22, and 2.7 kΩ to GND gives 0x23 (±5 % resistors).
  • Keep the I²C run between the boards short (under about 30 cm). The sensor goes near the ducts, and only the USB cable runs to the outlet.
  • The bare SDP31 is a small reflow-soldered part. Buy it on a breakout board, such as the SparkFun SparkX SDP31 Qwiic board, rather than hand-soldering the chip.
  • The pin numbers come from Sensirion's SDP3x-Digital datasheet. Check them against the current datasheet before laying out your own PCB. A breakout board prints its pin names, so the numbers only matter for a custom board.

Plumbing to the ducts

  • Use static pressure tips, the same kind a technician uses for a TESP reading. Put each through a hole sized for the tip (typically 3/8″) and seal it with a grommet. The tip faces into the airflow.
  • Supply tap: in the plenum sheet metal above the coil box, before the first branch. Look behind the panel before drilling; never drill near the coil or refrigerant lines.
  • Return tap: in the return duct, on the room side of the filter rack.
  • Keep both tubes short and about the same length. The SDP measures a tiny flow through itself, so long, thin tubing reads low. Sensirion's datasheet has a correction for long tubes.
  • Mount the sensor and ESP32 outside the ducts, above both taps, with the tubes sloping down to the taps.
  • The Trane ESP32 in this same space dropped to about −85 dBm. If this one does too, use an ESP32-DevKitC-32UE with an external antenna; the board setting is the same.

ESPHome firmware

Add it in Device Builder: + New device → Continue → skip, name it duct-static, then replace its YAML with this. It uses the same wifi_ssid, wifi_password and ota_password secrets as esphome-trane. Add one more line to Secrets: duct_static_api_key: "…", using the key Device Builder generates for the new device. The first install goes over USB; after that, Install → Wirelessly. The config passes esphome config on ESPHome 2026.6.5.

duct-static.yaml
# Duct static pressure: Sensirion SDP31 (±500 Pa) on an ESP32-DevKitC, I2C.
# Separate device from esphome-trane (no CAN). + port = supply plenum,
# − port = return plenum -> total external static pressure (TESP).
# Secrets come from Device Builder's secrets.yaml (same ota/wifi keys).
esphome:
  name: duct-static
  friendly_name: Duct Static

esp32:
  board: esp32dev
  framework:
    type: esp-idf

logger:

api:
  encryption:
    key: !secret duct_static_api_key

ota:
  - platform: esphome
    password: !secret ota_password

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  ap:
    ssid: "Duct Static Setup"

captive_portal:

i2c:
  sda: GPIO21
  scl: GPIO22
  frequency: 100kHz
  scan: true

sensor:
  # ESPHome reports SDP3x/SDP8xx in hPa and auto-detects the model.
  # SDP31 / SDP32: 0x21 (ADDR to GND). SDP810-500Pa: 0x25.
  - platform: sdp3x
    id: duct_static_pa
    name: "Pressure"
    address: 0x21
    update_interval: 2s
    unit_of_measurement: Pa
    accuracy_decimals: 1
    filters:
      - multiply: 100.0          # hPa -> Pa
      - sliding_window_moving_average:
          window_size: 5
          send_every: 5          # one value every 10 s

  - platform: copy
    source_id: duct_static_pa
    name: "Pressure inWC"
    unit_of_measurement: inWC
    device_class: ""
    accuracy_decimals: 3
    icon: mdi:gauge
    filters:
      - multiply: 0.00401463     # 1 Pa = 0.00401463 inWC

  - platform: wifi_signal
    name: "Wi-Fi Signal"
    update_interval: 60s

Home Assistant gets sensor.duct_static_pressure (Pa) and sensor.duct_static_pressure_inwc, one value every 10 s averaged from five 2 s reads.

Duct resistance in Home Assistant

This is the fan-law number from the Trane review: static divided by (rpm/1000)². It uses this sensor's static and the Trane blower motor speed, so it gives an independent check on the 0.27–0.28 baseline and on the Trane's own duct static reading. Put it in a template package:

packages/duct_resistance.yaml
template:
  - sensor:
      - name: "Duct Resistance (SDP31)"
        unique_id: duct_resistance_sdp31
        unit_of_measurement: "inWC/krpm²"
        state_class: measurement
        availability: >
          {{ states('sensor.duct_static_pressure_inwc') | float(none) is number
             and states('sensor.trane_air_handler_blower_motor_speed') | float(0) > 300 }}
        state: >
          {% set s = states('sensor.duct_static_pressure_inwc') | float %}
          {% set r = states('sensor.trane_air_handler_blower_motor_speed') | float %}
          {{ (s / (r / 1000) ** 2) | round(3) }}

Before and after the first power-up

  1. With the tubes off the sensor, the reading should sit within about ±1 Pa of zero. That confirms the wiring, the address and the zero point.
  2. With the blower on fan-On (maximum), expect about 1.0 inWC (~249 Pa) if your system matches the Trane reading. A negative value means P+ and P− are swapped.
  3. If the log says SDP3X: Couldn't read data, the I²C scan at boot lists the addresses it found: 0x21 for the SDP31, 0x25 for the SDP810.
