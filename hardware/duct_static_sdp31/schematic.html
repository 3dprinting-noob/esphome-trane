SDP31 Duct Static Node

One board design for JLCPCB, built twice. On each board, a Sensirion SDP31 differential-pressure sensor and an ESP32-C3 Wi-Fi module report to Home Assistant through ESPHome. Board A measures the pressure drop across the air filter. Board B measures supply static against the room. USB-C supplies power and programming. Neither board touches the Trane CAN bus.

range ±500 Pa = ±2.0 inWC your peak ≈ 1.0 inWC at 100 % blower I²C 0x21 on GPIO4 / GPIO5 BOM 13 lines · 20 placements per board · order 5

What changed from Rev A

Rev A was a dev board plus a breakout board, wired by hand. For JLCPCB everything is on one board:

  • An ESP32-C3-MINI-1 module replaces the DevKitC. Its USB is built in, so no USB-serial chip is needed.
  • USB-C power and an AMS1117 3.3 V regulator.
  • USB ESD protection.
  • Reset and boot buttons.
  • The SDP31 on the board, with its two ports facing up for tubing.

The Rev A wiring is kept in duct-static-devkitc.yaml for a quick breadboard prototype.

PCB layout rules

  • Two layers, 1.6 mm, with a solid GND pour on the bottom.
  • Antenna: put the ESP32-C3-MINI-1's antenna end at a board edge. Keep copper, traces and pour off both layers under and around the antenna, per Espressif's keep-out drawing in the module datasheet.
  • SDP31: at the opposite edge from the antenna, ports facing up with clear room for tubing. Keep it away from U3, which warms up.
  • C1 next to U2 pin 7, and C2 next to U1's 3V3 pad.
  • J1 at a board edge. Route USB_DP/USB_DM as a short, matched pair through U4, which sits close to J1.
  • Keep the I²C traces short. The sensor and the module can sit a few centimetres apart on the same board.
  • Do not wash or coat the board. The SDP31 has open ports; follow Sensirion's SDP3x handling and assembly instructions, and add "no washing, no conformal coating" to the JLCPCB order notes.
  • Four M3 mounting holes; the board goes in a small plastic box, not a metal one, for Wi-Fi.

Plumbing: two boards

  • The room reference must be at true house pressure. A normal utility room or basement is fine. A closet that doubles as the return path (a grille on the door or an open-bottom return) is not; in that case run Board B's P− tube out to the hallway.
  • Tube length only matters in total, because the SDP31 passes a tiny airflow through both tubes in series. Keep it short. Matching the two sides and matching heights make no measurable difference: the stack effect is well under 1 Pa per metre.
  • Use static pressure tips, sealed with grommets and facing into the airflow. Board A's taps go close to either side of the filter rack, with no fitting or elbow between tap and filter.
  • Supply tap: in the plenum sheet metal above the coil box. Look behind the panel first; never drill near the coil or refrigerant lines.
  • A use for a spare board: P+ to the room and P− to the blower side of the filter gives return static. Supply static plus return static is the total external static pressure the blower is rated against.

ESPHome firmware, one device per board

The two files are identical except for the device name, the entity names and the API key. In Device Builder, choose + New device → Continue → skip once for each: name one filter-dp and the other duct-supply, then paste the matching file. Both use your existing wifi_ssid, wifi_password and ota_password secrets. Add filter_dp_api_key and duct_supply_api_key to Secrets, using the keys Device Builder generates. Both files pass esphome config on ESPHome 2026.6.5.

filter-dp.yaml · Board A
# Board A: pressure drop across the air filter. Rev B JLCPCB board (ESP32-C3-MINI-1 + SDP31).
# P+ = return duct, room side of the filter; P- = return duct, blower side of the filter.
# A positive reading = drop across the filter; it rises as the filter loads.
# I2C: GPIO4 = SDA, GPIO5 = SCL. USB-C = native USB Serial/JTAG. No CAN connection.
esphome:
  name: filter-dp
  friendly_name: Filter

esp32:
  board: esp32-c3-devkitm-1
  framework:
    type: esp-idf

logger:
  hardware_uart: USB_SERIAL_JTAG

api:
  encryption:
    key: !secret filter_dp_api_key

ota:
  - platform: esphome
    password: !secret ota_password

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  ap:
    ssid: "Filter Setup"

captive_portal:

i2c:
  sda: GPIO4
  scl: GPIO5
  frequency: 100kHz
  scan: true

sensor:
  # ESPHome reports SDP3x/SDP8xx in hPa and auto-detects the model.
  # SDP31: 0x21 (ADDR to GND on the board).
  - platform: sdp3x
    id: duct_static_pa
    name: "Pressure Drop"
    address: 0x21
    update_interval: 2s
    unit_of_measurement: Pa
    accuracy_decimals: 1
    filters:
      - multiply: 100.0          # hPa -> Pa
      - sliding_window_moving_average:
          window_size: 5
          send_every: 5          # one value every 10 s

  - platform: copy
    source_id: duct_static_pa
    name: "Pressure Drop inWC"
    unit_of_measurement: inWC
    device_class: ""
    accuracy_decimals: 3
    icon: mdi:gauge
    filters:
      - multiply: 0.00401463     # 1 Pa = 0.00401463 inWC

  - platform: wifi_signal
    name: "Wi-Fi Signal"
    update_interval: 60s

Home Assistant gets sensor.filter_pressure_drop and sensor.filter_pressure_drop_inwc from Board A, and sensor.duct_supply_pressure and sensor.duct_supply_pressure_inwc from Board B. Each publishes one value every 10 s, the average of five 2 s reads.

  1. First flash over USB-C: plug the board into the computer running the browser and choose Install → Plug into this computer.
  2. If the port doesn't appear, hold BOOT, tap RESET, release BOOT, and try again.
  3. After that, updates go over Wi-Fi (Install → Wirelessly), and the board only needs a USB-C charger.
  4. Label each board A or B before it goes on the duct. The boards are identical, so only the firmware tells them apart.

Home Assistant: resistances and a dirty-filter alert

Both pressures depend on blower speed; pressure goes with the square of airflow. Dividing by (rpm/1000)², using the Trane blower motor speed, gives a resistance that stays comparable at any speed. Filter resistance compared with its clean value gives Filter Loading in %. A change reminder fires once it has stayed above 200 % for 6 hours. Double the clean drop is a common change point; adjust it to your filter maker's rated final resistance if you have it.

packages/duct_sensors_ha_package.yaml
# Home Assistant package for the two duct boards (drawing DS-01 rev B).
# Put in /config/packages/ (packages: !include_dir_named packages), restart.
# Resistances divide by (blower rpm / 1000)^2, so they stay comparable at any
# blower speed (fan law: pressure goes with the square of airflow).
input_number:
  filter_clean_resistance:
    name: Filter resistance when clean
    min: 0
    max: 1
    step: 0.001
    mode: box
    unit_of_measurement: "inWC/krpm²"
    icon: mdi:air-filter

input_button:
  filter_record_clean_baseline:
    name: Record clean-filter baseline
    icon: mdi:air-filter

template:
  - sensor:
      - name: "Supply Duct Resistance"
        unique_id: supply_duct_resistance
        unit_of_measurement: "inWC/krpm²"
        state_class: measurement
        availability: >
          {{ states('sensor.duct_supply_pressure_inwc') | float(none) is number
             and states('sensor.trane_air_handler_blower_motor_speed') | float(0) > 600 }}
        state: >
          {% set s = states('sensor.duct_supply_pressure_inwc') | float %}
          {% set r = states('sensor.trane_air_handler_blower_motor_speed') | float %}
          {{ (s / (r / 1000) ** 2) | round(3) }}
      - name: "Filter Resistance"
        unique_id: filter_resistance
        unit_of_measurement: "inWC/krpm²"
        state_class: measurement
        availability: >
          {{ states('sensor.filter_pressure_drop_inwc') | float(none) is number
             and states('sensor.trane_air_handler_blower_motor_speed') | float(0) > 600 }}
        state: >
          {% set d = states('sensor.filter_pressure_drop_inwc') | float %}
          {% set r = states('sensor.trane_air_handler_blower_motor_speed') | float %}
          {{ (d / (r / 1000) ** 2) | round(4) }}
      - name: "Filter Loading"
        unique_id: filter_loading
        unit_of_measurement: "%"
        state_class: measurement
        icon: mdi:air-filter
        availability: >
          {{ states('sensor.filter_resistance') | float(none) is number
             and states('input_number.filter_clean_resistance') | float(0) > 0 }}
        state: >
          {{ (states('sensor.filter_resistance') | float
              / states('input_number.filter_clean_resistance') | float * 100) | round(0) }}

automation:
  - id: filter_record_clean_baseline
    alias: Filter - record clean baseline
    description: Press after fitting a new filter, with the blower running steadily.
    triggers:
      - trigger: state
        entity_id: input_button.filter_record_clean_baseline
    conditions:
      - condition: template
        value_template: "{{ states('sensor.filter_resistance') | float(none) is number }}"
    actions:
      - action: input_number.set_value
        target:
          entity_id: input_number.filter_clean_resistance
        data:
          value: "{{ states('sensor.filter_resistance') | float }}"
  - id: filter_change_reminder
    alias: Filter - change reminder
    description: Notifies when the filter's resistance has stayed above double its clean value for 6 hours.
    triggers:
      - trigger: numeric_state
        entity_id: sensor.filter_loading
        above: 200
        for: "06:00:00"
    actions:
      - action: persistent_notification.create
        data:
          title: Air filter
          message: >
            Filter resistance is {{ states('sensor.filter_loading') }} % of its clean value.
            Time to change it, then press "Record clean-filter baseline".
  1. After fitting a new filter, run the blower steadily (fan-On) for a few minutes, then press Record clean-filter baseline.
  2. sensor.supply_duct_resistance is the independent check on the 0.27–0.28 duct-resistance baseline from the Trane review. Being supply-only, it will read lower than a total-static figure.

First power-up checks

  1. Before connecting the tubes, the reading should sit within about ±1 Pa of zero. That proves the sensor, the address and the zero point.
  2. On fan-On (maximum blower), Board B should read well above zero, a large share of the Trane's ~1.0 inWC, and Board A a small positive number. A negative value on either board means its P+ and P− tubes are swapped.
  3. The boot log's I²C scan should list 0x21. If it's missing, check the SDP31 solder joints and R1/R2.
